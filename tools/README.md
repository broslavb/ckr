# Автопідтягування ТТН із листів avto.pro

avto.pro не віддає номери ТТН через API, але шле їх листом:

> До вашого замовлення № 10514428 створено ТТН 20451519906235.

`avtopro_ttn.py` читає ці листи по IMAP і кладе пару «номер замовлення → ТТН»
у Firestore, у колекцію `avtopro_ttn`. Далі у CKR, вкладка **Отримання** →
кнопка **📥 Підтягнути ТТН з пошти** розставляє ТТН по позиціях, у яких
посилання веде на це замовлення avto.pro. Після цього працює звична
перевірка Нової Пошти, яка сама ставить «Отримано на складі».

Скрипт навмисно не чіпає самі калькуляції — він знає лише два числа.
Формат калькуляцій змінюється тільки в `index.html`, і парсер від цього
не ламається.

## Налаштування (робиться один раз)

**1. Пароль додатка для Gmail.** Звичайний пароль Google для IMAP не
підходить. Потрібна увімкнена двоетапна перевірка, далі:
myaccount.google.com → Безпека → Двоетапна перевірка → Паролі додатків.
Створити пароль, скопіювати ці 16 символів.

**2. Заповнити `config.txt`.** Одна команда створює файл і відкриває
його в редакторі:

    cd ~/Developer/CKR/tools && cp config.example.txt config.txt && open -e config.txt

Вписати адресу скриньки, пароль додатка і пароль від CKR, зберегти
(Cmd+S). Файл `config.txt` у git не потрапляє — він у `.gitignore`,
паролі лишаються тільки на цій машині.

**3. Перевірити:**

    python3 ~/Developer/CKR/tools/avtopro_ttn.py

Скрипт напише, скільки листів опрацював і що знайшов. Нічого
встановлювати не треба — лише стандартна бібліотека Python.

**4. Автозапуск раз на 15 хвилин:**

    cp ~/Developer/CKR/tools/com.ckr.avtopro-ttn.plist ~/Library/LaunchAgents/
    launchctl load ~/Library/LaunchAgents/com.ckr.avtopro-ttn.plist

Вимкнути:

    launchctl unload ~/Library/LaunchAgents/com.ckr.avtopro-ttn.plist

Поки iMac вимкнений, листи просто чекають — при наступному запуску
скрипт добере все, що накопичилось.

## Якщо щось не працює

Хід роботи пишеться в `tools/avtopro_ttn.log`.

- **«У config.txt не заповнено…»** — не заповнені обов'язкові поля.
- **`AUTHENTICATIONFAILED`** — Gmail не прийняв пароль: майже завжди це
  звичайний пароль замість пароля додатка.
- **«ТТН не знайдено»** — формат листа інший, ніж очікує регулярка.
  Зберегти лист файлом і показати Claude — правиться `RE_PAIR`.
- **`HTTP 403` від Firestore** — правила бази не дозволяють запис у
  `avtopro_ttn`. Треба дозволити авторизованим користувачам, або
  перевести скрипт на ключ службового акаунта.

## Стан

`tools/.state.json` зберігає UID останнього опрацьованого листа, щоб не
перечитувати ту саму пошту. Видалити файл — скрипт перечитає скриньку
з початку (нічого не зіпсує, ТТН просто перезапишуться тими самими).
